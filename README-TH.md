# อัปโหลด StoryCraft ทั้งเว็บขึ้น GitHub Pages

เวอร์ชัน 1.3 มีสองโหมด ใช้ UI และข้อมูลโปรเจกต์ชุดเดียวกัน:

- เว็บส่วนตัวบน Sites: ใช้เซิร์ฟเวอร์และคุกกี้คีย์แบบเข้ารหัสเดิม
- GitHub Pages: มี `index.html` และไฟล์เว็บที่ build แล้ว ไม่ต้องรัน Node หรือมีเซิร์ฟเวอร์ API เพิ่ม ผู้ใช้กรอก Gemini key ของตนเองในแท็บ แล้วเบราว์เซอร์เรียก Google โดยตรง

## อัปโหลดชุดพร้อมใช้

1. แตกไฟล์ `StoryCraft_Studio_GitHub_Pages_v1.3.zip`
2. เข้า repository `thanawid/storycraft-studio` หรือ repository ที่ต้องการ
3. เลือก **Add file → Upload files**
4. อัปโหลด `index.html`, โฟลเดอร์ `assets`, `storycraft-icon.svg` และไฟล์อื่นจาก ZIP ไปที่ราก repository อย่าวางทั้งหมดซ้อนอยู่ในโฟลเดอร์ชื่อ ZIP
5. กด **Commit changes**
6. เข้า **Settings → Pages** เลือก **Deploy from a branch → main → / (root)** แล้วกด **Save**
7. รอ GitHub แสดง URL ที่เผยแพร่สำเร็จ สำหรับ repository เดิม URL จะเป็น `https://thanawid.github.io/storycraft-studio/`

ไฟล์เว็บอ้างอิง assets แบบ relative จึงใช้ได้ทั้งเว็บที่รากโดเมนและ `/storycraft-studio/` ไม่ต้องแก้ path

## เริ่มใช้งาน

- เปิด **การเชื่อมต่อ Gemini** กรอกคีย์ แล้วเลือกรุ่นที่บัญชีมีโควตา
- คีย์ไม่ฝังใน source หรือ ZIP ไม่บันทึกใน localStorage, IndexedDB, cookie หรือ JSON โปรเจกต์ คีย์อยู่ในหน่วยความจำแท็บ เมื่อรีเฟรชหรือปิดแท็บจะต้องกรอกใหม่
- นี่เป็นการเชื่อม API จากเบราว์เซอร์โดยตรง ไม่ใช่การเก็บ secret ฝั่งเซิร์ฟเวอร์ คีย์ของผู้ใช้ยังเข้าถึงได้ในแท็บของผู้ใช้ จึงใช้กับอุปกรณ์และโค้ดที่ไว้ใจได้เท่านั้น
- GitHub Pages แบบฟรีเผยแพร่เว็บสาธารณะ ไม่ได้จำกัดให้คุณเปิดได้คนเดียว ผู้เปิดคนอื่นต้องใช้คีย์ของตนเอง และไม่เห็นโปรเจกต์ที่บันทึกในเบราว์เซอร์คุณ
- โปรเจกต์บนเว็บเดิมและ GitHub อยู่คนละโดเมน ข้อมูลจึงไม่ย้ายตามอัตโนมัติ: กด **สำรองโปรเจกต์** บนเว็บเดิม แล้ว **นำเข้าโปรเจกต์** บน GitHub
- การนำเข้าจะล้างผลอนุมัติช็อตเพื่อให้ตรวจต้นแบบอีกครั้ง ก่อนส่งออกวิดีโอ
- 503/429 เป็นข้อผิดพลาดหรือโควตาจาก Google การย้ายไป GitHub ไม่รับประกันว่าข้อผิดพลาดเหล่านี้จะหาย

วางสตอรีบอร์ดเอง จัดตัวละคร/สไตล์ สำรองข้อมูล และประกอบคลิปที่ตรวจผ่านได้โดยไม่เรียก AI การสร้างเรื่องด้วย AI ต้องมีอินเทอร์เน็ตและคีย์ การสร้างภาพ/คลิปด้วย Flow หรือ Kling ยังทำในเครื่องมือเหล่านั้น แล้วนำไฟล์กลับมาเหมือนเดิม

## เอฟเฟกต์หน้าเว็บ

การ์ดในหน้าแรกลอยเบา ๆ หน้าจอและกล่องข้อความปรากฏอย่างนุ่มนวล ปุ่มและการ์ดตอบสนองเมื่อชี้เมาส์ ปุ่ม **เอฟเฟกต์** มุมขวาบนเปิด/ปิดได้ ระบบเคารพการตั้งค่า Reduce motion ของอุปกรณ์ เอฟเฟกต์ไม่เปลี่ยนไฟล์ภาพต้นแบบ ใบหน้า เสียง หรือภาพในวิดีโอที่ส่งออก

## แก้ไข source และ build ใหม่

ZIP มีโฟลเดอร์ `source` สำหรับแก้ไขได้ แก้ `app/page.tsx` และ `app/studio.css` แล้วรันในโฟลเดอร์ `source`:

```bash
npm install
npm run build
```

นำ **เนื้อหาภายใน `dist`** ไปอัปโหลดทับไฟล์เว็บที่ราก repository ไม่ต้องอัปโหลด `node_modules` หรือคีย์ สำหรับ source หลักในโปรเจกต์ใช้ `pnpm build:github` จะได้โฟลเดอร์ `github-pages`

ชุดพร้อมใช้นี้ไม่มี server routes ของ Sites และไม่ต้องใช้ Cloudflare สำหรับการเปิดบน GitHub Pages
