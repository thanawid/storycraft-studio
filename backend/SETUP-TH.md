# StoryCraft Studio — ตั้งคีย์ครั้งเดียว ใช้ต่อได้
> เว็บ 1.7.0 ต้องอัปเดต Worker ด้วย เพื่อเพิ่ม /api/concepts ใช้ Secrets เดิม ไม่ต้องกรอกคีย์ใหม่


เว็บหลัก: https://thanawid.github.io/storycraft-studio/
หลังบ้านเดิม: https://storycraft-api.thanawid.workers.dev

เวอร์ชันนี้ย้ายการวางเรื่องด้วย Gemini ไปหลังบ้านเดียวกับ Kling แล้ว เว็บไม่ต้องรับ API key อีก
มีตัวเลือกจำการเข้าสู่ระบบบนเครื่องส่วนตัว 7 วัน รีเฟรชหรือเปิดใหม่ไม่ต้องกรอกรหัสทุกครั้ง

## อัปเดตตามลำดับนี้

### 1. สำรองโปรเจกต์
เปิดเว็บเดิม กดสำรองโปรเจกต์ เก็บ JSON ของแต่ละเรื่องไว้ก่อนอัปเดต ข้อมูลไม่ย้ายออกจากเบราว์เซอร์เอง

### 2. อัปเดต Worker เดิม
เข้า Cloudflare → Workers & Pages → storycraft-api → Edit code
วางโค้ด **backend/kling-worker.js ที่ราก ZIP** ทับโค้ดเดิมทั้งหมด แล้วกด Deploy
ไฟล์นี้ bundle แล้ว ใช้วางใน Dashboard ได้ทันที ไม่ต้องลงแพ็กเกจหรือแยกหลายไฟล์
**อย่าใช้ source/backend/kling-worker.js วางใน Dashboard** ไฟล์นั้นเป็น source ที่มี import ต้อง build ก่อน

### 3. ตั้ง Secrets ครั้งเดียว
ไป Settings → Variables and Secrets แล้วตรวจหรือเพิ่ม:

| ชื่อ | ประเภท | ค่าที่ใส่ |
| --- | --- | --- |
| STUDIO_PASSWORD | Secret | ใช้รหัสเจ้าของเดิม 24 ตัวของคุณได้ (ขั้นต่ำของรุ่นนี้ 16 ตัว) |
| KLING_API_KEY | Secret | คงคีย์ Kling เดิมไว้ |
| GEMINI_API_KEY | Secret | เพิ่ม Gemini key ที่คุณใช้กับ Google AI Studio |
| ALLOWED_ORIGIN | Text | https://thanawid.github.io |
| GEMINI_MODEL | Text | เช่น gemini-3.8-flash หรือรุ่นที่บัญชีของคุณมีโควตา |

กด Save/Deploy ให้ค่ามีผล ไม่ต้องส่งคีย์หรือรหัสมาในแชตหรือใส่ใน GitHub
GEMINI_API_KEY เป็นค่าที่เพิ่มใหม่จากรุ่น 1.4.0 ส่วนคีย์ Kling และรหัสเดิมใช้ต่อได้
หากไม่มีคีย์ Gemini ยังเข้าสู่ระบบและใช้ Kling ได้ บริการทั้งสองไม่บังคับให้ตั้งพร้อมกัน
โมเดลเริ่มต้นหากไม่ได้ตั้ง GEMINI_MODEL คือ gemini-3.8-flash การมีคีย์ไม่รับประกันโควตาหรือสิทธิ์โมเดล

### 4. อัปเดตเว็บ GitHub
อัปโหลด index.html, assets และ storycraft-icon.svg ที่ราก ZIP ทับไฟล์เว็บเดิมใน thanawid/storycraft-studio
index.html ต้องอยู่ที่ราก repository ไม่ซ้อนในโฟลเดอร์ชื่อ ZIP
Pages ยังใช้ main → / (root) รอเผยแพร่ จากนั้นรีเฟรชให้เห็น v1.5.0

### 5. เข้าสู่ระบบครั้งแรก
เปิดเว็บ → การเชื่อมต่อ AI
ช่องหลังบ้านกรอก URL เดิมไว้ให้แล้ว ใส่รหัสเจ้าของเดิมแล้วติ๊ก “จำการเข้าสู่ระบบบนเครื่องนี้ 7 วัน”
กดเข้าสู่ระบบและใช้ AI จากนั้นเว็บจะแสดงว่าฝั่ง Gemini/Kling ตั้งคีย์แล้วหรือยัง
กด “ตรวจคีย์และสิทธิ์โมเดล” เพื่อตรวจ Gemini ได้โดยไม่สร้างเรื่อง การตรวจนี้ไม่ยืนยันว่าเหลือโควตาสร้างเท่าไร

## การจำเครื่อง

- คีย์ AI ทั้งสองอยู่เฉพาะ Cloudflare Secrets ไม่ส่งกลับเบราว์เซอร์ ไม่อยู่ในโปรเจกต์หรือ ZIP
- รหัสเจ้าของถูกล้างจากช่องหลังส่งและไม่บันทึกลง localStorage
- ถ้าเลือกจำเครื่อง เบราว์เซอร์เก็บเซสชันที่ลงลายเซ็นและหมดอายุภายใน 7 วัน เซสชันนี้ให้สิทธิ์ใช้เครดิต จึงควรเลือกเฉพาะเครื่องส่วนตัว
- ไม่เลือกจำเครื่อง เซสชันอยู่ในหน่วยความจำแท็บ 1 ชั่วโมงเหมือนเดิม
- หมดอายุแล้วต้องเข้าสู่ระบบเจ้าของใหม่ คีย์ AI ไม่ต้องกรอกอีก
- “ออกจากระบบ / ลืมเครื่องนี้” ลบเซสชันจากเครื่องนี้ หากต้องยกเลิกเซสชันที่ออกไปทั้งหมดให้เปลี่ยน STUDIO_PASSWORD ใน Cloudflare
- หากเบราว์เซอร์บล็อก localStorage จะใช้ได้เฉพาะแท็บและเว็บจะแจ้งว่าไม่ได้จำเครื่อง
- ห้ามฝังคีย์ใน frontend เพื่อทำให้ไม่ต้องเข้าสู่ระบบ เพราะผู้เปิดเว็บสาธารณะจะเข้าถึงคีย์ได้

## เริ่มสร้างงาน

สร้างโปรเจกต์ MV / หนังสั้น / ละคร / นิทาน → ใส่เรื่องย่อ เนื้อเพลง หรือเสียง → ล็อกตัวละครและสไตล์ → ยืนยันส่งข้อมูล → สร้างเรื่อง
Gemini รับเสียงและภาพอ้างอิงต้นฉบับผ่านหลังบ้าน มีการตรวจ SHA-256 ก่อนส่ง รูปต้นแบบไม่ถูกแปลงหรือซ่อมใบหน้า
ช็อตใหม่ที่วางเองเริ่มที่ 5 วินาที กด “เปิดช็อต / สร้างคลิป” เพื่อทำงานต่อ
Kling ยังใช้ 2.6, 720p, ปิดเสียง และสร้างทีละช็อต 5/10 วินาที
รองรับตัวละครหนึ่งคนด้วยภาพต้นแบบเดิมเป็น first frame ไม่ส่งหลายภาพอ้างอิงแยกในรุ่นนี้
ดาวน์โหลดคลิปจากลิงก์งานแล้วแนบกลับในช็อต จากนั้นตรวจความต่อเนื่องก่อนอนุมัติและประกอบวิดีโอ
คำสั่งล็อกตัวละครไม่รับประกันว่าโมเดลจะคงใบหน้าได้ทุกเฟรม หากเปลี่ยนใบหน้าต้องปฏิเสธช็อตและปรับมุม ไม่ใช้ AI ซ่อมหน้า
คลิปจาก Kling ปิดเสียง เสียงพูดสำหรับหนัง/ละคร/นิทานยังต้องเตรียมแยก ส่วน MV ใช้เพลงต้นฉบับ
การสร้างภาพนิ่งอัตโนมัติ การสร้างหลายช็อตพร้อมกัน และการดาวน์โหลดคลิปเข้าฐานข้อมูลอัตโนมัติยังไม่ได้เพิ่มในรุ่นนี้

## เมื่อสร้างไม่ผ่าน

- ขึ้น “อัปเดตโค้ด Worker 1.5.0”: เว็บใหม่แต่หลังบ้านยังเก่า อัปเดต Worker ก่อน
- 401 พร้อมเซสชันหมดอายุ: เข้าสู่ระบบเจ้าของใหม่ ไม่ต้องกรอกคีย์ AI
- Provider key ไม่มีสิทธิ์: ตรวจคีย์ที่ Cloudflare และสิทธิ์บัญชีผู้ให้บริการ การตรวจคีย์ไม่ทำให้เซสชันเจ้าของหาย
- Gemini 429: โควตาหรือจำนวนคำขอถึงขีดจำกัด ตรวจ Google AI Studio การย้ายคีย์มาหลังบ้านไม่เพิ่มโควตา และไม่มีเวลาที่รับประกันว่าจะกลับมาใช้ได้
- Gemini 503: บริการยังไม่พร้อม มีปุ่มลองใหม่ ระบบไม่ส่งซ้ำหรือเปลี่ยนผู้ให้บริการเอง
- งาน Kling ขึ้น unknown: ตรวจสถานะเลขงานเดิมและ Generation History ก่อนส่งใหม่ การปิดเว็บไม่ยกเลิกงานที่ส่งแล้ว
- CORS: ALLOWED_ORIGIN ต้องเป็น https://thanawid.github.io ไม่มี path และไม่มี / ท้าย

## สำหรับแก้ source ต่อ
เข้า source แล้วรัน npm install, npm run typecheck, npm test, npm run build และ npm run build:worker
เว็บพร้อมใช้จะอยู่ใน source/dist ส่วน Worker ไฟล์เดียวอยู่ใน source/worker-dist/kling-worker.js
ไฟล์ source/backend/kling-worker.js ต้อง build ก่อนวาง Cloudflare Dashboard
ไม่ต้องอัปโหลด node_modules, worker-dist, dist ซ้ำ หรือไฟล์ Secrets ลง GitHub

## การตรวจรอบนี้
ทดสอบข้อมูลจำลองครอบคลุมการจำเครื่อง เปิดแท็บใหม่ ลืมเครื่อง เซสชันหมดอายุ เปลี่ยนรหัสเจ้าของ การส่ง multipart เสียงและต้นแบบผ่าน Worker ไม่เปิดเผยคีย์ และไม่ส่งคำขอสร้างซ้ำ
ไม่เรียก AI ด้วยคีย์จริง ไม่ใช้ credits/units และยังไม่ได้ทดสอบหน้าจอจริงในเบราว์เซอร์
