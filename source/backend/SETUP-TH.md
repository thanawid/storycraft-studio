# เชื่อม Kling กับเว็บหลัก StoryCraft Studio 1.4.0

ชุดนี้เตรียมโค้ดตัวเชื่อมไว้แล้ว ยังไม่ได้เผยแพร่ Worker และไม่ได้ลองสร้างกับคีย์จริง
ไม่มีคีย์หรือรหัสของคุณในไฟล์นี้ การทดสอบใช้ข้อมูลจำลอง ไม่ใช้ units

## 1. อัปเดตเว็บ GitHub

สำรองโปรเจกต์จากเว็บก่อน แล้วอัปโหลด index.html, assets และ storycraft-icon.svg ที่ราก ZIP ทับของเดิมใน thanawid/storycraft-studio
วาง index.html ที่ราก repository ไม่ซ้อนในโฟลเดอร์ ZIP รอ Pages เผยแพร่ แล้วรีเฟรชเว็บ
หน้าเว็บจะแสดงเวอร์ชัน 1.4.0 และใน “การเชื่อมต่อ AI” มีส่วน Kling เพิ่มขึ้น

## 2. สร้างหลังบ้าน Cloudflare

1. เปิด https://dash.cloudflare.com/ สมัครหรือเข้าสู่ระบบบัญชีของคุณ
2. ไป Workers & Pages → Create application → สร้าง Worker แบบ Hello World
3. ตั้งชื่อ เช่น storycraft-api แล้ว Deploy
4. เปิด Edit code ลบโค้ดตัวอย่าง แล้ววางเนื้อหาทั้งหมดจากไฟล์ kling-worker.js ในโฟลเดอร์นี้ จากนั้น Deploy
5. ไป Settings → Variables and Secrets เพิ่มค่าต่อไปนี้ แล้ว Deploy การตั้งค่าใหม่:

| ชื่อ | ประเภท | ใส่อะไร |
| --- | --- | --- |
| KLING_API_KEY | Secret | API key ใหม่จากหน้า Kling API Platform ของคุณ |
| STUDIO_PASSWORD | Secret | รหัสเจ้าของที่สุ่มอย่างน้อย 24 ตัว แนะนำ 32 ตัว เก็บในตัวจัดการรหัสผ่าน |
| ALLOWED_ORIGIN | Text | https://thanawid.github.io (ไม่มี /storycraft-studio/ และไม่มี / ท้าย) |

ห้ามใส่คีย์จริงในไฟล์ JS, repository, README หรือข้อความแชต
โค้ดนี้ใช้ API key แบบ Bearer ของ API ใหม่ ไม่ใช้ Access Key/Secret Key แบบ JWT ของ API รุ่นเก่า
ใช้ URL workers.dev ของ Worker เช่น https://storycraft-api.ชื่อบัญชี.workers.dev
ชุดเริ่มต้นนี้รองรับ workers.dev เท่านั้น หากใช้โดเมนเองต้องแก้การตรวจ URL และ CSP ก่อน
การใช้ Cloudflare อยู่ภายใต้โควตาและแผนบัญชีของคุณ ส่วนการสร้างคลิป Kling ใช้ units ที่ซื้อไว้

## 3. เชื่อมจากเว็บ

เปิด https://thanawid.github.io/storycraft-studio/ → การเชื่อมต่อ AI → ส่วน Kling
กรอก Worker URL และ STUDIO_PASSWORD แล้วกดเชื่อมหลังบ้าน
ข้อความเข้าสู่ระบบยืนยันเฉพาะหลังบ้าน ไม่ได้ตรวจว่า Kling key หรือเครดิตสร้างจริงผ่านแล้ว
รหัสถูกส่ง HTTPS ไป Worker ของคุณ เซสชันในเว็บอยู่เฉพาะหน่วยความจำแท็บ 1 ชั่วโมง ไม่อยู่ใน JSON โปรเจกต์
ผู้เปิดเว็บอื่นไม่สามารถเรียกหลังบ้านเพื่อใช้ units โดยไม่มีรหัสเจ้าของ ให้เก็บรหัสเป็นความลับ

## 4. ลองหนึ่งช็อต

1. เพิ่มภาพเริ่ม JPG/PNG ไม่เกิน 4 MB กว้างและสูงอย่างน้อย 300 px อัตราส่วน 1:2.5 ถึง 2.5:1
2. รุ่นแรกใช้ Kling 2.6, 720p, ปิดเสียง รับ 5 หรือ 10 วินาที ตั้งความยาวช็อตให้ตรง
3. ล็อกสไตล์ หากมีตัวละครต้องล็อกตัวละครและใช้ไฟล์ภาพต้นแบบเดิมหนึ่งคนเป็นภาพเริ่ม โหมดนี้ยังไม่ส่งหลายภาพอ้างอิงแยกต่างหาก
4. ตรวจภาพเริ่มครบทุกข้อแล้วกด “ตรวจผ่าน”
5. ติ๊กอนุญาตส่งภาพและใช้ units แล้วกดสร้างคลิปหนึ่งครั้ง
6. กด “ตรวจสถานะงานเดิม” เป็นระยะ สถานะ submitted/processing ยังต้องรอ; succeeded คือสำเร็จ; failed คือล้มเหลว
7. เมื่อสำเร็จเปิดลิงก์คลิป ดาวน์โหลด แล้วใช้ “เปลี่ยนภาพหรือคลิป” แนบคลิปกลับในช็อต
8. เทียบใบหน้า ทรงผม ชุดและการเคลื่อนไหวกับต้นแบบอีกครั้งก่อนอนุมัติคลิปและประกอบวิดีโอ

คำสั่งล็อกตัวละครช่วยกำกับโมเดล แต่ไม่รับประกันว่าใบหน้าจะไม่เปลี่ยน ระบบไม่ตรวจยืนยันใบหน้าอัตโนมัติ
ไม่มีการสร้างภาพนิ่งด้วย Kling ในรุ่นนี้ และยังไม่สร้างทุกช็อตพร้อมกัน
คลิปปิดเสียง หากเป็นหนัง/ละคร/นิทานยังต้องเตรียมเสียงพูดแยก การวิเคราะห์เพลง/วางเรื่องยังใช้ Gemini เดิม

## ถ้าเน็ตหลุดหรือขึ้น unknown

เลขติดตามและภาพเริ่มจะถูกบันทึกก่อนส่งคำขอสร้างคลิป ไม่ส่ง POST ซ้ำอัตโนมัติ
เชื่อม Worker เดิมใหม่ แล้วกดตรวจสถานะงานเดิม เลข custom task ID แสดงในช็อตและอยู่ในไฟล์สำรองโปรเจกต์
หากไม่พบงาน ให้ตรวจ Generation History ในบัญชี Kling และรอสักครู่ก่อนตัดสินใจเริ่มใหม่
ปุ่มล้างเลขติดตามลบเฉพาะข้อมูลในโปรเจกต์ ไม่ยกเลิกงานหรือคืน units ต้องตรวจบัญชีก่อนกด
การปิดเว็บไม่ยกเลิกงานที่ส่งไปแล้ว ลิงก์ผลลัพธ์จาก Kling มีอายุจำกัด (เอกสารระบุ 30 วัน) ควรดาวน์โหลดทันที

## ปัญหาที่พบบ่อย

- 401: รหัสเจ้าของผิดหรือเซสชันหมดอายุ เชื่อมใหม่
- 403/CORS: ALLOWED_ORIGIN ต้องเป็น https://thanawid.github.io หรือคุณเปิดเว็บจากโดเมนอื่น
- 503 หลังบ้าน: ยังไม่ได้ตั้ง Secrets หรือรหัสสั้นกว่า 24 ตัว
- Kling ปฏิเสธคำขอ: ตรวจ API key แบบใหม่, แพ็กวิดีโอ, สิทธิ์รุ่น 2.6 และยอด units ใน Kling
- Prompt ยาวเกิน 2,500 ตัว: ย่อคำอธิบายฉากและตัวละคร ระบบไม่ตัดคำสั่งล็อกใบหน้าเงียบ ๆ
- Google Gemini 503: เป็นอีกบริการหนึ่ง การต่อ Kling ไม่แก้ความพร้อมของ Gemini
